# 决策前自检清单（每次动代码前强制执行）

## 每次改代码前必须回答：

### 1. 用户确认了吗？
- [ ] 这个改动是用户明确要求的，还是我自己推断的？
- [ ] 如果是推断的 → **先问用户，不动代码**
- [ ] 如果涉及架构/分类/触发条件 → **必须确认**

### 2. 物理推导了吗？
- [ ] 公式是从物理过程推导的，还是从目标数字反推的？
- [ ] 如果从数字反推 → **停，先写物理模型**
- [ ] 每个参数必须有物理含义注释

### 3. 有现实数据吗？
- [ ] 这个模块的校准锚点有哪些？（列出数据来源）
- [ ] 数据和公式的差距物理上有解释吗？（不是调参凑的）

### 4. 做的是分类还是连续逻辑？
- [ ] 有没有引入硬编码的分段/"if space>X then Y"/"精英vs普通"？
- [ ] 所有阈值都应该是连续函数的自然交汇点

### 5. 改了哪些文件？
- [ ] 改动清单列出来
- [ ] 同步到工作区了吗？

## 核心工作原则（假设变更的连锁反应）：

### 假设变更法则
**当任何核心假设被重新定义后，所有基于该假设的推导都必须重新审视。**

这不是"测试"的问题，而是**逻辑一致性**的问题：
- 假设 A → 推导 B → 结论 C
- 如果 A 变为 A'，那么 B 和 C 的推导基础已不存在
- **不能假设 B 和 C 仍然成立**

### 适用场景：
| 假设变更类型 | 需要重新审视的内容 |
|-------------|------------------|
| 模块物理定义改变 | 该模块的所有测试、调用逻辑、情境路由 |
| 情境触发条件改变 | 情境判断逻辑、属性权重、结果映射 |
| 属性含义/权重改变 | 所有使用该属性的公式、测试场景 |
| 分类标准改变（如tackle vs contest的区分） | 分类逻辑、路由规则、边界案例 |
| 连续/离散逻辑改变 | 所有阈值、过渡区域、极端情况处理 |

### 执行清单（假设变更后）：
- [ ] **识别**：哪些推导/代码/测试依赖这个假设？
- [ ] **废止**：旧的推导结果不能直接继承
- [ ] **重推**：基于新假设重新推导
- [ ] **验证**：新的推导是否符合物理逻辑和现实数据？
- [ ] **同步**：相关文件、测试、文档全部更新

## 禁止事项：
- ❌ 未经确认改架构/触发条件/分类
- ❌ 先凑数据再写公式
- ❌ 凭记忆改文件（先用 Read 读最新内容）
- ❌ 改完不跑测试
- ❌ **假设重新定义后，声称旧推导"仍然成立"**——必须基于新假设重新推导。旧结论和新假设的正确性之间没有继承关系。
